# Legacy content compatibility audit

Audit date: 2026-09-12. Source baseline HEAD: `d3f98ed139c09ceaf6afa7bc49a3d73420f9aab0` with concurrent working-tree edits preserved.

Scope: six retained content routes, legacy WritingEditor/CmsMarkdown, content adapter, full content-editor and content-draft-operation helpers, their relevant tests and source-only mutation dependencies. Read current repository instructions and workspace implementation plan. No browser, provider, private draft, database or credential access. The user wants optional, read-mostly Operations; this audit does not restore retired workflows.

## Compatibility disposition

The legacy D1 page_content/content_draft_operations model is **not** the current Git-backed Website editor. Keep source records and endpoints without creating identity redirects or enabling writes. Operations navigation labels these routes Legacy content diagnostics; current Website has a separate entry.

The old WritingEditor was still imported by a reachable route and presented editable fields plus Save draft/Publish selected draft. Its adminMutationFetch requires `/api/admin/auth/session`, but `apps/admin/src/pages/api/admin/auth` is absent. This is source evidence of an unavailable normal client prerequisite, not a live provider test. Under root authorization, replaced that UI with a read-only record/source/history viewer; did not restore authentication or alter dormant APIs/backend helpers.
