## Display semantics

Keep connection, freshness and execution separate. Each observation needs an origin, subject ID, observed-at instant and explicit validity window.

| Display      | Minimum evidence                                                                                                                                             |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Connected    | Successful authorized observation from the named connection adapter; name the transport in detail.                                                           |
| Disconnected | Explicit transport/session disconnect observation. Distinguish a user-disabled connection.                                                                   |
| Unavailable  | Adapter missing, denied, failed or unreachable; prior values may be retained with their original timestamp.                                                  |
| Stale        | Last successful observation exceeded the source-specific freshness window. Preserve its prior outcome.                                                       |
| Running      | Fresh explicit execution-start/heartbeat and run identity from the runtime owner. A reachable host, enabled schedule or replayed checkpoint is insufficient. |
| Idle         | Fresh explicit no-current-run observation from the runtime owner. Silence is unknown or stale, never idle.                                                   |
| Last contact | Most recent verified device/adapter contact instant. Do not substitute page render, snapshot generation, task edit or last historical checkpoint time.       |

## Per-record actions

| Action     | Supported now                   | Intended behavior and missing capability                                                                                                                                                                                                                                    |

| Reconnect  | Read-feed retry only            | A selected machine/loop needs a runtime-owned adapter to retry its existing authorized transport and return fresh connection evidence. No credential changes or new enrollment.                                                                                             |
| Disconnect | No                              | Stop the selected observation connection or collection subscription; retain evidence and records. Specify whether the underlying loop continues. A separate service-stop action must never be implied. Needs exact target, adapter capability and native controls.          |
| Archive    | No persisted per-record support | Hide the listing from the default view with an Archived view and Restore. Preserve connection/loop execution and evidence. Needs presentation storage and recovery scope; never use task archival as a proxy.                                                               |
| Delete     | No                              | Remove precisely identified connection configuration only after showing retained/deleted data and effects. Native approval and a scoped runtime implementation are required. Not personal-record deletion, credential revocation or host/service retirement by implication. |
